# 小说章节整理

2026-10-18。本轮基于已有 `chapters.py` 和阅读 API 增强，独立分支 `codex/chapters-editor`，叠加未合并的 #13。正式版本仍 v0.6.4，未发布。

## 已实现

- 阅读器“整理章节”进入按需加载编辑页；自动识别为草稿，用户确认后保存。支持改标题、指定 Unicode 字符位置拆分、连续章节合并、调整相邻边界、上移/下移、重新识别比较、载入旧目录并确认恢复。
- 复用现有中文/数字/Chapter/Markdown/特殊标题规则，新增 h4–h6、围栏代码排除、保留原始换行与开头空白覆盖。卷/部标题保留为独立目录项，暂不是可折叠树；不规则标题可手动拆分命名。
- 新增只追加的目录快照表。恢复创建新快照；目录编辑不修改正文或原文件。每次保存验证全文范围无重叠/缺口，正文起点只能跳过完整识别标题，顺序与原文位置独立。
- 正文 SHA256 和目录基线版本保护，过期保存返回 409；正文变化后保留旧历史，阅读器提示且不套用过期目录。当前目录历史最多展示最近 100 条，底层不因此删除历史。
- 大 TXT/Markdown 预览被截断时，按需从原文件读取全文；EPUB 使用原有解析器的严格 spine 模式，处理缺失引用、实体及路径编码，不用 30000 字符预览冒充全文。UTF-16 BOM 优先识别，保留原有 GB18030 等回退。
- 全文整理上限 32 MiB、EPUB 正文解压累计限额 32 MiB/400条、目录上限5000项；章节列表每页50项，源片段最多2000字符。异常返回明确错误，原文件保留。

## 验证边界

自动测试覆盖中文数字/阿拉伯数字/全角数字、序章/楔子/番外/后记/终章、英文 Chapter、Markdown h6、无标题、卷/部、围栏代码、CRLF、UTF-16与GB18030、450万字节以上正文尾部、EPUB spine顺序与缺失引用、重复上传、范围缺口/隐藏正文拒绝、版本冲突与恢复。

真实本机原创项目中的 13 个 TXT 做只读规则扫描，原始文件 SHA256 前后一致。识别到 1178 项标题候选，很多来自设定稿的 Markdown 小标题；**不是已经确认的小说章节，不是实际长篇小说准确率证明**。用户选择本轮只预览，未正式入库。私有标题、正文、原路径、完整结果只在 `.cache/chapters-real-private.json`，不提交仓库。

生成的长篇：2,003,899 字符、401目录项，同文本单次测量、启用 tracemalloc：旧拆分约1.299秒/544,946 bytes峰值；本轮约1.310秒/522,481 bytes峰值。CPU变化很小，无总体提速结论；不是独立进程RSS或渲染耗时。曾采用逐行复制扫描围栏，已改为只扫描围栏标记，避免额外全文行列表。

浏览器隔离生成样本实际完成：改名/合并、拆分/排序、保存、旧目录恢复成第三个版本、阅读器使用已确认目录且保留合并内容。1440×1000与390×844检查；窄屏编辑器文档宽380、阅读器宽390，无横向溢出；未捕获控制台error。公开截图只含生成文本，见 `docs/screenshots/chapters/`。

## 尚未完成

- 尚无用户提供的完整长篇/真实 EPUB 正本验收，长篇和EPUB测试均为生成样本。没有规则能保证所有设定稿/小说标题识别正确，必须预览审核。
- 字符偏移是 Python Unicode 码点，与 UTF-8 字节和 JavaScript UTF-16 code unit 不同；UI直接使用服务器数值，不用 JS 字符串偏移推算。暂不提供拖选文本划界。
- 草稿只在当前页面，离开前需确认保存；自动目录字数实时计算，手动改动字数在保存时重新计算。卷级树、目录全文搜索、完整书籍版本快照和文本差异属于后续增强。
- 目录快照不保存旧正文。正文变更后可看旧目录，但不能将其边界直接恢复到另一正文；文本版本对比/恢复在下一独立目标实现。
- 同一大文件每次打开章节仍需按需读取与校验全文，尚无持续的外部文件增量索引；不新增后台常驻服务。过大文件需分卷，超限不静默截断。
- 没有执行AI调用或将私有正文发往远程服务。AI章节批次、证据和世界观审核将在抽取增强阶段处理。

后续总需求见 [Feature Backlog](FEATURE_BACKLOG.md)；Live2D实时渲染、桌面安装/便携、备份恢复、签名更新和发布流水线仍保留。
