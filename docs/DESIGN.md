# 设计与动效

v0.6.0 起，Front 的界面按一套统一的设计系统重做。本文记录这套系统**参考了什么、遵守什么规则**，方便以后的页面保持一致。

## 视觉方向

参考 [Nephele Workshop](https://nephele.arisfusion.com/)（一个面向画师的桌面工作站）官网展示的气质：**深靛夜色底、极淡的网格、单一的雾紫强调色、悬浮的圆角侧栏外壳、胶囊形的分段控件、创作热力图**。
Front 只借鉴了这种观感与布局思路，没有使用 Nephele 的任何代码、图片、字体文件或品牌素材。

| 设计令牌 | 深色（默认） | 浅色 |
| --- | --- | --- |
| 背景 `--bg` | `#15151f` + 40px 极淡网格 | `#f5f5f8` + 网格 |
| 内容面 `--panel` / `--panel2` | `#1c1c29` / `#24243a` | `#ffffff` / `#f1f0f6` |
| 文字 `--text` / `--muted` / `--faint` | `#eaeaf5` / `#adafca` / `#7d7f9c` | `#1b1b28` / `#5d5f78` / `#8a8ca3` |
| 唯一强调色 `--accent` | `#9a6ad0`（雾紫） | `#7c4dbd` |
| 状态色 | 青 `--ok`、琥珀 `--warn`、红 `--danger`，只用于状态 | 同左（更深） |
| 圆角 | 8 / 12 / 18px（控件 / 卡片 / 外壳与弹窗） | 同左 |

全部颜色都走语义变量，页面里不再写死颜色（关系网的节点 / 关系类型配色除外，它们本身是数据）。侧栏底部可以切换深色 / 浅色，并且可以收起成图标栏，两项都记在浏览器本地。

## 克制原则

来自 [apple-design-skills](https://github.com/s1gmamale1/apple-design-skills)（MIT）中的 restraint / anti-slop 清单，按 Front 是“工具型界面”来取舍：

- **一个强调色**：主按钮从粉紫渐变改为实心雾紫胶囊；进度条、相关度条改为同色系。不再给标题加渐变字。
- **玻璃只给外壳**：只有侧栏、顶栏、提示条和弹窗遮罩使用半透明 + 模糊；内容卡片都是实心的。
- **层级靠字号与留白**：页面标题上方加小号大写的分组眉标（`LIBRARY`、`WIKI`、`DRAW`…），总览页用大号问候语做唯一的“主角”。
- **内容优先**：素材库改为画廊式网格——图片本身无边框，标题和日期放在图下，悬停时才出现强调色描边。
- **图标统一**：全部换成同一套线性图标（[Lucide](https://lucide.dev)，ISC），替换了旧版混用的各种字符符号。

## 动效原则

动效全部用 [GSAP](https://gsap.com) 实现，写法遵循 [gsap-skills](https://github.com/greensock/gsap-skills)（MIT）：只动 `transform` / `opacity`（加少量 `filter: blur`），组件卸载即清理，动画结束清除内联样式。
节奏与取舍遵循 [design-motion-principles](https://github.com/kylezantos/design-motion-principles)（MIT）的“频率门槛”，Front 属于生产力工具，以 Emil Kowalski 一派的“快、少、有目的”为主：

| 场景 | 触发频率 | 处理 |
| --- | --- | --- |
| 切换页面 | 经常 | 只做进入：上移 8px + 由 3px 模糊对焦，340ms `power3.out`；离开不做动画 |
| 首次出现的列表 / 卡片（`v-reveal`） | 偶尔 | 依次淡入，每项间隔 25ms，最多 24 项，同一元素只动一次 |
| 弹窗 | 偶尔 | 遮罩淡入 180ms；面板从 0.97 缩放（不从 0 开始），260ms |
| 侧栏高亮 | 经常 | 一个高亮块在导航项之间滑动（300ms），而不是每一项各自闪烁 |
| 提示条 | 偶尔 | 进入时上移 + 去模糊，离开更轻更快（160ms） |
| 总览数字、热力图 | 每次打开总览 | 数字从 0 滚动到目标值（700ms），热力图按周依次显现 |
| 悬停、点击 | 非常频繁 | 不用 GSAP，只有 150ms 的颜色过渡和按下时 0.97 的缩放 |
| 键盘快捷键（Ctrl/⌘ K、`/` 聚焦搜索） | — | 不做任何动画 |

系统开启“减少动态效果”（`prefers-reduced-motion: reduce`）时，所有 GSAP 动画直接跳到最终状态，CSS 过渡缩短到 0.01ms。不使用循环闪烁、呼吸灯之类吸引注意力的动画。

### 从 awesome-ai-motion 学到的

浏览了 [awesome-ai-motion](https://github.com/guanmo-ai/awesome-ai-motion)（MIT，收录的作品版权归各作者）里与界面相关的案例，提炼成几条在 Front 里落地的想法（只学思路，没有使用其中任何作品素材）：

- **“一个形状串起整套 UI”**：侧栏只有一个高亮块，在导航项之间连续移动，让“我在哪”有空间上的连续性。
- **窗口按时间线依次登场**：页面里的卡片、列表首次出现时按顺序淡入，而不是整页同时闪现。
- **数据随动画“长出来”**：总览的统计数字滚动、热力图按周显现，只在进入总览时发生一次。
- 这些案例大多是宣传短片，动效预算远高于工具界面；Front 只取其中“连续性”和“顺序感”，时长全部压在 350ms 以内。

## 实现位置

- `frontend/src/style.css`：设计令牌、深浅主题、全局组件样式（卡片、按钮、胶囊、分段控件、画廊网格……）
- `frontend/src/motion.js`：所有 GSAP 动效与 `v-reveal` 指令
- `frontend/src/App.vue`：外壳（悬浮侧栏、高亮块、玻璃顶栏、主题与折叠、快捷键）
- `frontend/src/components/Ico.vue`：旧字符图标到 Lucide 图标的映射
