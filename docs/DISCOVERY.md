# 扫描来源与资料发现

入口 `/discovery` 懒加载。每个来源保存名称、实际路径、类型、深度、忽略规则、预算、稳定UID/并发版本和最近结果。只在明确点击扫描时使用现有2worker/32队列，不启动监控器或AI服务。

## 流程与边界

1. 选择具体本地文件夹，保存来源；不默认扫描硬盘，不接受整盘、网络共享或Front数据目录，不遍历符号链接/Windows重解析点。路径不可修改，换目录需登记新来源；移除来源仅删配置，保留素材、预览和原文件。
2. 手动扫描。文件类型/目录名提供作品边界、正文、封面、附录和标签候选；优先使用明确的正文/封面/model3目录锚点，将较深层插图关联到其作品边界候选。没有锚点时只按第一层目录分组，不作语义识别或确定来源。
3. 预览与导入分离。通用素材归档复用LibraryImport/Asset/ingest；世界观归档复用ProjectImport。支持原地索引或明确托管复制，不要求独立素材属于某个世界观，不自动创建/合并作品、角色或标签。详细文本/图片在现有项目预览按需查看。
4. 暂停/取消保留已完成指纹与部分预览；继续会重新枚举、校验文件状态并复用已完成Hash，不是字节偏移续读。每轮报告独立，旧报告不就地修改；中断报告不能正式导入。重启标记interrupted，绝不自动重放扫描或导入。

只有同一配置下的完整基线才能判断缺失。触及预算、首次扫描或配置改变时缺失显示未知，不删除资料、修复文件或将未扫描项目当成丢失。变化是文件身份/大小/时间戳变化候选，不是文本/图像语义差异；指纹缓存只是预览加速，正式导入仍由既有机制复核实际Hash。

## 扫描预算

默认深度4（根为0）、1000个可识别文件、20000个全部目录项、声明总大小32GiB、单文件Hash16MiB、每轮Hash读取256MiB、60秒协作预算。硬上限分别为32层、5000文件、50000目录项、1TiB、256MiB、1GiB、600秒。忽略规则最多40条，每条200字符，大小写不敏感glob匹配相对路径或文件名；已知开发/系统缓存目录默认跳过。

大文件可以仅保留元数据。模型权重和EXE始终只登记文件信息，应在专用模型/游戏工作区管理，不因调高Hash预算进入通用素材复制。无有效Hash、模型关联目录或错误条目不能确认导入。新预览的Hash分块1MiB，读中增长最多读声明大小+1字节就拒绝；不执行任何扫描文件。

ZIP先读取有限EOCD，目录最多1000条/2MiB、文件≤32MiB，限制条目64MiB/声明展开256MiB/压缩比200；路径、链接、加密或超预算报告诊断，不解压、不读取条目正文、不宣称CRC已验证。其他压缩格式在本入口只登记格式/文件信息，完整预览仍用既有专用模块。目录/块间检查时间和取消；操作系统阻塞I/O不保证硬实时超时，未验证网络盘/故障磁盘最坏耗时。

## 接口和存储

- `GET/POST /api/discovery-roots`，列表20项，最多100项。
- `GET/PATCH /api/discovery-roots/{id}`；PATCH要求uid/version，活动任务期间不改配置。
- `POST .../{id}/scan`，`POST .../{id}/control/pause|cancel`，`POST .../{id}/remove`，均要求uid/version。
- 报告复用`/api/project-previews/{report_id}`、文件详情和图片接口，页面每次50项；部分扫描禁止导入，有限完整结果明确提示不完整范围。

仅新增discovery_roots配置表，现有表字段不改；升级前沿用一致性快照。预览/指纹仍在project-previews，完整备份沿用既有OWNED范围；隔离恢复验证配置/UID/报告/旧资料。私有路径和报告留本地，不发送到外部服务。路径预览在resolve前逐段检查链接/重解析点；普通文件系统竞态并不等同沙箱或防御拥有本机写权限的攻击者。

验收、性能和未完成能力见[扫描验收](audits/discovery/ROOTS_20261108.md)。联网匹配、角色卡、多模式对话、原生文件夹选择器与Live2D运行接口分别推进，不能因为有扫描入口标为全部完成。
