# PR C：确认章节、原文证据与人工审核

## 复用与数据闭环

仍使用现有章节编辑器、OpenAI兼容Provider、extract解析器、角色/关系CRUD和2工作线程/32排队的持久任务模块。新工作流是原“抽取角色”页默认模式，不是另一套AI平台。旧接口继续兼容，但也改为仅按明确同名汇总，不再因别名交集自动合并候选；唯一同名重复写入复用已有角色，歧义时要求明确ID。

先保存当前正文的确认目录，再明确选择小说ID、世界观ID、作品ID和章节。界面预览片段、章节字数、服务与发送范围；没有勾选发送确认不会调用服务。目录版本或正文哈希不符拒绝请求，超限明确报错，不静默截断。每章独立分片，默认3000字符，单批最多200片/8MiB，不跨章拼接；每次输出最多请求8000tokens，超过256,000字符的响应拒绝解析。

每个片段和完成结果在SQLite持久化。失败、取消、重启中断后，明确重试只处理未完成片段，不自动重发远程请求；服务地址或模型变更要求新批次。当前网络调用返回/超时后才可完成取消。排队时取消会与任务终态对齐，避免永久显示处理中。启动中断恢复是状态恢复，不声称断电原子恢复实测。

候选必须附能在该正文快照逐字定位的引句，保存确认目录、正文SHA256、章节及Unicode字符区间。引句重复时明确标记首个匹配位置需核对；不伪称语义验证或已确认事实。区分叙述者陈述、角色说法、推断与未确认类别；置信度为AI自述且未经校准。性别无独立原文依据保留未知。跨章只按明确同名汇总，保留各次观察和差异提示，别名仅提供可审核ID建议。

人工逐页勾选人物、可编辑设定、明确选择已有ID，关系另行勾选且双方均需审核。新建/补充、审核映射、证据在同一事务；重复审核幂等，默认不覆盖已有设定。关系仍为AI待确认，复用原关系网最终确认。人物详情和关系控制面板按需读取证据，返回原审核批次。已审核对象删除后不把证据绑定到复用ID的新对象。正文或归属改变后，旧批次证据保留，但不能直接写入正式百科。

同小说/世界观/作品的两次抽取可以比较候选人物与关系的新增/本次未出现；章节范围不同会明确提示。没有把“本次未出现”当作设定删除。小型待审图只显示前24节点，不初始化额外图引擎；完整关系网仍用原模块。

## DeepSeek配置与验证边界

DeepSeek官方提供OpenAI兼容API，Front原Provider拼接`/chat/completions`，无需另装SDK。在本机“设置”增加兼容服务，base URL填`https://api.deepseek.com`，模型使用账户当前可用模型（2026-10-24官方示例为`deepseek-flash`），密钥仅在本机填写，再选择为对话服务。[官方文档](https://api-docs.deepseek.com/)。不要把密钥放入聊天、仓库或截图。

用户目前只表示计划接入，尚未配置密钥，也未选择真实正文发送范围。本轮没有向DeepSeek或其他远程服务发送原创项目，不能宣称真实AI抽取质量、长篇召回率或费用已验收。

- 全量185项后端测试通过，生产构建通过。新增回归为生成小说和进程内模拟Provider：证据位置、幻觉过滤、歧义别名、事务回滚、跨世界隔离、正文变化、重复抽取/审核、失败重试与排队取消。30章生成文本验证了跨片段区间与重复引句标记；这不是长篇真实模型能力测试。
- 浏览器使用明确标记“非AI实测”的生成批次：章节预览、选人/关系、审核写入、人物详情证据、返回批次、桌面和390px窄屏；无横向溢出、控制台无错误。没有启动外部Mock服务或把生成候选称为真实模型输出。公开截图仅生成文本。
- 本机20次HTTP读取2人/2片段批次，中位3.37ms，响应3,631bytes；不代表大库/模型推理延迟。审核组件独立chunk约16.7KiB（gzip约7KiB），证据读取另约2KiB；无新增运行依赖或默认推理服务。

## 限制及待办

组织归属暂为有待审核的特征建议，未自动创建组织百科；时间线与语义设定冲突分析未实现，描述差异提示仅是不同观察，并非AI裁定。别名/代词跨片段指代及没有双方名字的关系可能漏检；优先避免无依据合并。当前候选统一加载后在界面每页50项，1000人物以上需分批，超大型结果尚待服务端候选分页和RSS验收。

批次正文快照会占用额外私有存储，暂无清理/保留期限界面；响应、任务和当前目录有上限，不等于任意长篇一次处理。历史批次与引用仍保留，完整媒体备份/恢复是v0.7必须继续的工作。真实DeepSeek效果、真实长篇小说、网络限流成本和实际崩溃恢复需后续明确授权范围后验证。OC、Live2D实时渲染、Windows安装/便携与签名更新任务没有取消。
