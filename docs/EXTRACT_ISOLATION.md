# 抽取审核的世界观隔离修复

这是从现有抽取代码发现的安全缺口定向修复，不代表“有证据的小说抽取”阶段已完成。分支 `codex/extract-world-guard`，基于项目预览 #15 继续堆叠。

## 修复行为

- 未选择世界观时，已知人物候选仅来自未归属人物，不再把所有世界观的人名与别名一起用于抽取提示或关系匹配。
- 已归属某世界观的小说，必须选择同一世界观后才允许继续抽取；不一致返回422，在调用AI前拒绝。不存在的世界观返回404。
- 审核提交时，所有 `existing_id` 先检查存在和世界观ID一致。伪造其他世界观ID、未归属模式引用已归属人物、过期/缺失ID均拒绝，不静默创建替代角色。
- 整批校验先于新增/追加动作，避免前半批已落库、后半批才发现越界。不更新原人物，不自动跨世界合并同名人物。
- 兼容未归属小说由用户明确选择目标世界观后抽取；不自动将小说本身改为该世界观。世界观名字相同但ID不同，仍独立。

## 验证与边界

回归覆盖未归属候选不泄露其他世界观别名、同名不同世界观、伪造已有ID、整批拒绝不写入、原人物不变、正确世界观正常提交，以及源小说不匹配在AI调用前拒绝。原有模拟AI抽取/审核回归仍通过。

全部使用生成文本、生成世界观与本地进程内模拟Provider；未向真实AI发送用户资料。额外启动本地模拟AI演示进程被自动审批策略拦截（只返回策略阻止，未提供细分原因），未重试启动，以进程内API回归代替。没有宣称本修复做过真实AI或浏览器抽取演示。前端没有修改，仍运行生产构建。

性能仅增加已有角色的主键归属检查，无新依赖、后台服务或绘图/推理初始化；未独立测量大批次性能。原有全量已知角色候选、分块数量、结果别名合并和轮询仍有优化空间。

**后续仍需实现**：明确作品绑定、按确认章节分批、全文完整性、引用位置/文本证据、事实/说法/推测分类、跨章合并审核、冲突建议、绑定不可变抽取来源、批量审核图。这个补丁只是先封住现有跨世界观ID写入路径，不替代上述功能。
