# 完整媒体备份与隔离恢复

本轮优先交付原任务PR4，先保护资料，再增加OC新表。当前main基线3aedea0，无待合并PR；保留原数据库在线快照机制，不重写导入、素材或版本系统。

## 已实现

`/backups`懒加载工作区和设置入口。备份是本机文件夹：front.db一致性快照、内容寻址objects、manifest.json。包含media（图片/附件/托管模型包及版本保留文件）、thumbs、project-previews及独立jobs.sqlite3快照；不递归复制备份、恢复副本、临时导入或服务日志。数据库包含所有百科、版本及关联，也可能包含本机API凭据；备份应私有保存，不能公开提交。

备份等待已有资料操作/后台任务完成，再暂停新的写入；界面返回423中文提示，后台工作等待，查询和取消可继续。SQLite写屏障在复制期间保持，数据库与托管内容不会被正常应用写入并发改变。外部直接SQL写入不经过本机门禁，但会受SQLite写锁约束；多个Front进程使用同目录不受支持。

逐文件1MiB流式复制并计算SHA256，检查文件变化及已登记Hash，内容相同的备份对象只存一份。源缺失、读权限、链接越界、内容变化与Hash不符分开报告，不把部分备份标为complete。取消/失败保留状态，重试创建新的一致快照，不复用不完整事务。

原地索引默认仅记录路径、存在状态和已登记Hash；用户可以逐项选择额外包含的外部素材。外部SD模型和Live2D目录保留引用，不默认复制，也暂不支持整目录选择。已作为素材托管的模型包随media备份。原始目录不修改。

恢复前逐对象校验Hash，检查SQLite完整性、已知表/列和格式版本，拒绝未知新结构或路径穿越。再次恢复时重新校验，复制到全新`restores/<id>`，只迁移该副本，检查外键、完整性及落盘Hash，再原子公布为verified。选择包含的外部素材重定位到副本内；未包含的引用保持原路径。任何失败保留`.partial`诊断，当前实例不替换。恢复记录持久可查询。

## 使用与边界

创建→选择备份→校验预览→检查已包含/仅引用/缺失/无法备份→明确确认→创建独立恢复副本。partial备份默认不能恢复，需明确接受缺失项。**正式使用恢复副本需要停止Front，将其作为FRONT_DATA_DIR重启**；没有在线替换当前SQLite，没有自动清空原资料，没有ZIP上传或远端下载向导。备份文件夹可复制到另一磁盘，再输入其本机路径。

当前不加密、不签名，不是同步服务或异地容灾。清单32MiB上限；大型百万文件清单、所有历史库与断电测试尚未验收。目录下未属于上述已知管理区域的自定义文件不自动收集。完整性校验能检测损坏，不能证明来源可信。恢复副本数据库迁移不初始化AI、摄像头或渲染器。
