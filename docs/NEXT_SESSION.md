## Character Soul 的实现与验证边界

源分支[技术文档](https://github.com/Fiesty-Abyss/Front/blob/codex/character-soul/docs/CHARACTER_SOUL.md)和[验收记录](https://github.com/Fiesty-Abyss/Front/blob/codex/character-soul/docs/audits/soul/ACCEPTANCE_20261109.md)。未合并前不是main已上线功能。

- 懒加载 /souls；新增SoulIdentity/SoulLink/SoulMemory引用表及独立FTS，不吞并百科、OC、Card、Chat、Voice或Asset。
- 名称不作身份；记录UID/创建身份、世界观/作品/角色、VoiceModel版本。删除后数字ID复用、同名跨世界观、来源修改/停用/重绑均有回归。
- 来源消息保存会话/分支/Hash/有限证据；兄弟分支不继承经历，中间祖先改挂也停止旧证据召回。关联重新启用与恢复单次递增revision，拒绝旧窗口写入。
- 新记忆待审且禁用引用；内容编辑重新待审，恢复追加历史；拒绝/冲突/停用撤销许可。冲突为人工标记，不是AI语义分析。
- 最多检查200条候选、返回30条，默认4000/上限12000字符并带引用。recall始终sent_to_ai:false，没有自动提取、embedding或实际聊天注入。
- 停用可恢复，不等于不可逆删除历史或清除旧备份；后两项未实现。

当前限制：正式来源更新后，旧来源指纹保留追溯并停止召回；需新建记忆显式引用新来源，不自动重绑旧档案。聊天来源跳会话工作区，精确消息/分支深链仍待；Voice/Live2D当前也仅跳工作区。大关联列表/全部世界观候选分页、批量重新引用、多来源/长分支召回性能仍待增强。固定记忆不能绕过来源/范围/审核或预算。

真实浏览器生成流程：创建独立Soul→关联Card与两会话→原文证据→待审排除→人工确认→另一显式会话召回→编辑/恢复/撤销→重启持久化。390px无横向溢出、主题、部分Tab、错误输入保留及控制台已验；不是实际AI、原生Soul、完整键盘/内存/GPU或干净安装验收。分页JSON准备与API已验，浏览器下载落盘未验。

真实HTTP完整备份0issues；隔离恢复verified、活动库不替换。活动生成库与恢复副本的Soul、记忆UID/第7次修订、审核许可及11个EntityVersion一致；integrity=ok、外键0。没有读取个人库或真实聊天。

生成ASGI/tracemalloc基线：1k/10k记忆，30条分页中位19.03/22.15ms、18,775/18,836B；8条召回14.88/33.56ms、7,561/7,593B。10k逻辑DB10,989,568B，不含每条历史成本；EXPLAIN使用原有soul_id索引。不是RSS/GPU/Heap或相对旧版改善百分比。
