# PR A：正式导入与世界观归档

## 已实现

- 基于现有项目预览，逐项/本页/全部确认；可编辑标题和候选分类，选择已有世界观ID或创建新世界观，再明确选择原地索引/托管模式。批量添加全局和本世界局部标签。候选人物文档只归档为资料，不擅自创建或合并正式人物。
- 原地索引不复制原始文件；路径和指纹在独立受控绑定表，不能用可编辑meta伪造。托管模式复用原有1MiB分块处理与完整SHA256内容路径，不覆盖原件；再次导入重新哈希验证，缓存不是导入授权。
- 世界观引用复用同一个通用素材，不为多个世界复制原始大文件。每个引用独立保存标签、收藏、0–5星、0–100喜爱度及备注，变更不会污染其他世界观。
- 在原世界观页新增按需加载的“项目档案”标签，而非再建一套独立百科。可归档本世界已有素材/人物/条目/笔记引用，明确关联作品/关系或其他世界资料；跨世界关联需显式确认。搜索和筛选在world_id范围内，SQL分页，不带正文列表。
- 局部标签独立表，支持层级/别名、编辑、世界观范围检查与循环拒绝；全局标签复用原目录，合并/删除会更新归档引用，使用计数含归档。
- 导入批次与每个文件状态入SQLite，逐项事务提交；失败部分保留，恢复跳过已提交项，启动时将未结束批次标记中断。复用有界任务池；项目导入单实例串行去重，等待锁也可取消。
- 失效/修改的索引文件报告409，不静默读取新内容。重新预览相同内容的新位置可修复失效绑定；不同内容需要版本审核，不能覆盖旧档案。移除引用/删除索引记录不删除原件。
- 新表/旧列升级前创建并校验front.db在线备份，失败停止升级。合成旧库测试实际恢复快照并保留旧内容，不重置数据库。

## 数据兼容与限制

新增表，不重建Tag/Asset等历史表，不强制迁移所有资料。不依赖世界观名字唯一；引用不改变原资料的world_id。SQLite账本与主库仍保留原架构，无额外常驻数据库。

- 同路径内容变化不会自动覆写已有版本；版本导入在PR B提供。原地索引不自动保留旧图片/工程原字节；固定媒体版本需要明确托管副本，不能把失效外部路径当作已保存图像版本。
- 预览模型文件夹仍交给模型专用扫描；本轮正式确认只接受有哈希的文件。托管沿用上传大小上限，原地可流式哈希更大文件，但解析器可能降级。DOCX等正文仍是可读取预览范围，不宣称所有格式完整编辑。
- 正在处理的解析器/托管单文件操作不能立即中断；提交前/文件间检查取消。严重磁盘错误可能导致任务停在中断状态，下次启动恢复，不保证未提交内容保留。落盘与SQLite不是跨系统原子事务，失败可能留下无引用托管文件，不自动删除。
- 仅支持一个Front实例使用同一数据目录；跨进程并发的去重、长期百万级搜索与完整媒体备份/恢复仍待验收。数据库快照不含媒体和外部原件，不称为整库备份。
- 世界观原生条目通过显式“归档本世界已有条目引用”进入统一档案筛选；原百科各视图仍保留。引用源删除后显示失效，引用本身不会复活或合并原对象。
