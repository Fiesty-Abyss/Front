## 上下文

`chatcontext.units/trim` 按用户请求及其后回复形成语义单元；前导开场白是单独单元。保留全部 system（包括已激活世界书）、最新完整单元；旧单元整体移除，绝不只留其 assistant。40 条历史消息限制同样不能切半轮；必要指令/当前单元超过字符预算则 422，不截断人设。字符不是 token。

预览分别显示 omitted message / turn 数量和被省略的原消息；开场白单独计为 introduction，不混进问答轮数。发送元数据只记位置、角色、字符数和计数，不重复保存旧正文。真正的模型请求遵循当前分支原顺序，不改数据库历史、别的分支或世界书。预算验证失败会回滚本次尚未提交的用户消息/head；实际调用失败则保留已提交的有效用户输入。

## SSE 与互斥

响应持有显式 iterator 所有权，即使首次 SSE 之前断开也释放未启动的生成占位。收到 start、部分 delta、超时、错误类型/JSON、缺失结束标志和输出超额均有回归。部分回复以 interrupted/error 保存，空结果不造空 assistant；上游关闭/保存完成后才发送终结事件并允许下一轮。旧响应的二次清理不会释放新一轮 token。

浏览器读流用 finally cancel/release；EOF 没有 done/error 是失败，不当成功清空草稿。stop、pagehide 和卸载中止接收并尽可能通知已知任务；迟到响应不刷新已离开的页面。

**外部同步推理不能保证立即停止**：正在阻塞的 next() 仍持有本会话/全局名额，直到返回再清理。前端明确说明只是停止接收、外部服务可能仍处理。没有“停止即停止远端计算”或费用退款承诺。生成期间编辑/分支/模型切换仍 409。

## 会话列表与迁移

新增 `/api/ai/sessions/page`，默认 50、最多 100，按 updated_at DESC + id DESC 排序，游标绑定筛选。标题搜索为字面子串。列投影只取 head 的 60 字与当前页消息总数，不加载 ORM 消息树；详情按需读取。游标不是跨请求数据库快照：新更新的会话需要刷新首页；未变化条目同时间排序稳定。

旧 `/sessions` 保留数组形状及原字段、准确当前分支消息数，新增 limit/offset 并默认限制 50、最多100。**依赖旧无界全量行为的外部调用方需要分页**；不能把此变化称作无界语义完全不变。旧分支深度仅对当前页用 ID-only CTE，现代摘要不需要走分支。

实际 EXPLAIN 原先会话排序 SCAN+临时 B-tree，消息数量分组 SCAN+临时 B-tree。仅为该证据新增 `(updated_at,id)`、`ChatMessage(session_id)` 索引，之后 covering index/no temp B-tree。已有库缺索引时先 SQLite 一致快照再幂等建索引；不重写消息或素材。旧线性聊天升级、追加索引、备份恢复及已有行保持有回归。

Windows 本机、隔离 SQLite、每会话一条 8 KiB 生成消息；同一 corpus/ASGI/tracemalloc，对照旧全量实现和新首页50条。不是进程 RSS、GPU、冷启动或真实滚动测量。时延是本次仪器采样，不能当 SLA。

另复现省略预览回传过大：120轮、每条约4KiB的生成长对话，在1,024字符请求预算下，原预览却返回 **1,007,365 bytes**（因为全部省略正文也随响应返回）。现改成默认20条、上限100、每条240字符的带原始位置摘要分页；生成meta只存最多20个单元/每单元8个位置样本及精确总计数/截止位置，不随全部历史增长。真实请求内容不因摘要缩短而改变，原消息不改写。新回归证明首/次页无重复，head与精确计数一致，响应<16KiB（本生成ASCII条件）。这仍不代表聊天详情消息树已经实现分页。
