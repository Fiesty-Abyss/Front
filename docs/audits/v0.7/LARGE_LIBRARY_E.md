# 阶段E：大型资料库隔离探测与正确性瓶颈

本报告读取隔离生成缓存中的`report.json`、`world-index-comparison.json`、`generated-images.json`和`search-correctness.json`，只公开脱敏数值和方法。测试未读取、修改或压测正式用户库，也未使用用户小说、图片、音频或模型权重。

**本轮已完成的是部分后端隔离探测，不是阶段E全部验收。** 1万/5万/10万是SQL直接生成的元数据和FTS；100张PNG才是实际生成字节通过上传/解析/Hash/缩略图API的文件测试。二者不能合并表述为“10万真实素材导入通过”。前半部分保留修复前/隔离实验口径；文末另列本PR产品修复、1000张PNG与真实网络/浏览器/备份候选复测，均不等于正式发布。

## 环境与数据层次

主探测以进程内ASGI TestClient调用API，没有真实网络传输或浏览器渲染时间。SQL种子按1000条分批写入Asset、FTS和标签关联，逐步累计到1万、5万、10万。使用10个生成世界观、20个全局生成标签；每条素材只关联一个标签。一个收藏集固定关联前1万素材。

标题为Generated asset加序号，world_id按ID模10分配，tag_id按ID模20分配，日期在固定28天内循环；每5条中1条kind为novel。novel正文只是短小重复生成文本，供元数据/搜索负载使用，不是长篇小说、章节编辑器或真实文档导入。这是固定生成分布，不是生产资料的统计分布；没有创建复杂人物关系、数百模型、音频专辑或多层标签结构。

### SQL种子和数据库文件

后两行耗时只对应新增记录，不是重新构建整个目标规模。SQL直写跳过真实文件扫描、导入业务校验、Hash、解析、缩略图和后台任务编排，**不能当作文件导入吞吐**。

| 累计元数据数 | 本轮新增 | SQL/FTS种子秒数 | checkpoint后front.db文件大小 |
| --- | --- | --- | --- |
| 10,000 | 10,000 | 0.321 | 13,090,816 / 12.48 MiB |
| 50,000 | 40,000 | 1.189 | 60,882,944 / 58.06 MiB |
| 100,000 | 50,000 | 1.519 | 119,238,656 / 113.71 MiB |

数据库大小只包含当时的front.db逻辑文件长度，不等于所有媒体、备份、WAL、缩略图和物理磁盘总占用。报告未提供这些规模的独立后端峰值RSS或浏览器heap。

## 初始API探测

每个规模的每类请求重复5次；p50为中位数，表中第二个数为5次中的最大值。均为进程内调用，不能称为真实页面首屏或滚动延迟。“首页”表示列表第一页，不是应用冷启动。

| 请求 | 1万 p50/max ms | 5万 p50/max ms | 10万 p50/max ms | 10万时响应字节 | 10万时reported total |
| --- | --- | --- | --- | --- | --- |
| 首页，limit=60 | 4.82 / 103.85 | 4.68 / 6.87 | 6.87 / 7.72 | 27,686 | 100,000 |
| 无搜索末页，offset=N−60 | 4.29 / 4.71 | 5.19 / 5.54 | 6.91 / 8.27 | 27,552 | 100,000 |
| 世界观3，limit=60 | 9.13 / 10.53 | 28.48 / 29.70 | 50.75 / 50.96 | 27,625 | 10,000 |
| 双标签3与4（无匹配） | 7.80 / 10.29 | 23.85 / 25.87 | 52.38 / 57.44 | 22 | 0 |
| 窄命中FTS：q=asset 001 | 17.48 / 17.83 | 13.35 / 14.78 | 14.55 / 16.44 | 27,617 | 1,000 |
| 短查询：q=as | 48.89 / 58.71 | 42.26 / 42.71 | 45.92 / 47.87 | 27,625 | 10,000 |
| 收藏列表：limit=20 | 424.49 / 477.27 | 410.85 / 491.95 | 411.47 / 476.31 | 6,893,147 | 1 |

重要边界：

- 每个素材只有一个标签，双选tag=3和tag=4必然无匹配。22字节/total=0不能证明复杂多标签正向筛选、层级或别名的性能和正确性。
- 初始FTS查询`asset 001`只命中1000条，是窄结果集合。它的14.55ms不能与后文宽命中`Generated`的402.10ms直接比较。
- 短查询`as`在5万和10万规模仍reported total=10000是截断问题，不是正确的低延迟结果。该类延迟必须与正确性一起解读。
- `/api/collections?limit=20`限制的是收藏集数量，不限制内部成员。这里只有1个收藏集，却带出1万成员的6,893,147字节响应，约6.89MB（6.57MiB）。该固定1万成员负载在三种总库规模下都存在，不能误称为1万个收藏集测试。

## 已复现瓶颈一：搜索1万ID截断

补测在同一个ASGI客户端、同一数据库上先运行原实现，再以monkeypatch替换为SQL子查询候选。数据为10万条生成元数据加100张实际上传的生成PNG；这个数据库已包含后文的实验世界观复合索引。没有网络/渲染耗时，缓存为热态。

每阶段、每查询10次。报告字段名为p95，但实际取10项排序后的第9项，只是小样本近似高分位，不作标准总体p95或置信区间。下表延迟格式为p50 / 该近似高分位。

| 查询条件 | 原实现total / returned | SQL候选total / returned | 原实现 ms | SQL候选 ms |
| --- | --- | --- | --- | --- |
| q=as，limit=60 | 10,000 / 60 | 100,000 / 60 | 44.14 / 51.16 | 207.10 / 211.82 |
| q=Generated，limit=60 | 10,000 / 60 | 100,100 / 60 | 586.63 / 621.12 | 402.10 / 456.54 |
| q=as，world_id=3，limit=60 | 1,000 / 60 | 10,000 / 60 | 36.57 / 41.59 | 131.16 / 134.88 |
| q=as，offset=99940，limit=60 | 10,000 / 0 | 100,000 / 60 | 55.73 / 64.82 | 376.21 / 425.56 |

结果说明：

- 原实现的Python结果ID集合在1万处截断，导致宽搜索总数错误，叠加世界观过滤时只看到部分结果，offset=99940时返回空页。
- SQL子查询候选在这些生成用例中恢复了短查询10万、世界观1万及深页60条结果；`Generated`命中100100，因为新增100张PNG也匹配，不是重复生成了100个元数据记录。
- 正确性恢复有延迟取舍：短查询p50为44.14→207.10ms，世界观叠加36.57→131.16ms，深页55.73→376.21ms。旧深页返回0与新深页返回60本来就不是同等有效工作量。
- 宽FTS p50为586.63→402.10ms，同时恢复完整命中数；这只描述本轮同条件补测，不能外推所有查询语法、中文分词或全局搜索性能。

**产品状态：**此处是隔离monkeypatch实验。搜索候选仍须进入正式代码、补正确性/删除更新/分页/范围隔离回归、核对执行计划和最终CI后，才能写为产品修复完成。不能为保留旧的低耗时而继续接受错误总数。

## 已复现瓶颈二：世界观过滤走全扫描

主探测的世界观EXPLAIN为`SCAN assets USING INDEX ix_assets_work_date`；单标签计划为资产排序索引扫描加相关子查询，关联表通过`(asset_id, tag_id)`覆盖索引查找。这个单标签EXPLAIN不是计时中的双标签请求，不应混作复杂标签完整计划。

在隔离数据库增加实验索引`ix_assets_world_date_id`后，单独对世界观查询复测：

| 实验状态 | p50 ms | EXPLAIN摘要 |
| --- | --- | --- |
| 原索引 | 54.37 | SCAN assets USING INDEX ix_assets_work_date |
| 实验复合索引 | 4.24 | SEARCH assets USING COVERING INDEX ix_assets_world_date_id (world_id=?) |

该结果为目标查询提供了索引候选证据，**只发生在隔离实验库，未修改产品数据库或迁移逻辑**。原JSON还记录了高分位字段，但未附该实验的采样轮数，本文不把它包装成大样本统计结论。落地前应检查实际API的count/排序/字段回表、其他查询代价及旧库索引迁移测试，而不是把实验CREATE INDEX视为产品已升级。

## 已复现瓶颈三：收藏列表带出1万成员

1万成员收藏集的列表响应始终约6.89MB；100k总库时p50为411.47ms、5次最大476.31ms。序列化的大响应还可能影响浏览器解析和布局，但本轮没有实际测量浏览器耗时，因此不报告推测出的前端帧率。

产品修复仍待做。候选方向是收藏列表返回摘要/成员计数/封面，成员通过分页读取；保持现有素材引用、收藏详情和调用方兼容，不再复制底层文件或另建收藏存储。修复后应验证页面显示数量、成员顺序、旧接口兼容和批量管理，再复测响应大小及浏览器交互。
