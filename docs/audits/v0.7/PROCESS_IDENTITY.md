# Windows 进程采样归属修复 · 2026-11-08

实际原生隔离实例揭示 `desktop/profiling.py` 仅按 ParentProcessId 递归：Windows 复用退出进程的 PID 后，更早产生的旧子树会被误计入新 Front。第一次采样误含 3 个更早建立的无关进程；它们未被关闭。该次未校正的 12 进程总量不作性能结论，也不能据此判断内存改善。

现在用同一份 CIM 清单的创建时间核对每条父子边；旧子树不递归。根缺失、时间未知、重复 PID/身份不明均保守处理，未确认子边时总量为 null。每次内存测量还在 OpenProcess 持有的句柄上用 GetProcessTimes 校验创建时间，避免清单与采样间的 PID 复用；CIM 微秒与 FILETIME 100ns 精度差仅容忍 10 ticks。GPU 计数后再次核对进程身份，变化时 GPU 标为不可测。

没有修改被测进程、工作集、优先级或 GPU 配置。只导出核对后的进程名/角色、创建时间和指标；不导出命令行、页面内容、令牌或文件路径。此脚本只在显式执行时运行，不加入软件启动路径。没有新依赖、数据库/应用数据迁移或前端变化。

本机隔离预览包的早期短时样本：9 个身份已核对的进程，未知子边 0；工作集求和 508.70 MiB、PrivateBytes 332.00 MiB、私有驻留 236.18 MiB、可共享驻留 271.97 MiB、比例驻留估算 275.04 MiB。GPU 计数专用 61.09 MiB、共享 112.96 MiB。工作集重复计算共享页；私有提交不是实际物理 RAM；比例值受 Windows ShareCount 上限影响，仅估算；GPU 不与 CPU 数值相加。

该样本在启动早期采集，未等待首屏可交互，不是峰值、稳定空闲、泄漏、冷启动或标准 TTI 验收。另一次最终脚本对自有源码后端+控制台 2 进程采样为工作集124.80 MiB/私有提交103.75 MiB，未涵盖浏览器，不能代表整个 Web Front。两个样本都不与历史不同负载作优化百分比比较。原生包源仍为 PR55 的测试合并8075e37，本 PR只改变采样工具。

回归覆盖：旧父PID复用与孙树、缺失根/未知时间/重复身份、部分子树未知总量、GPU期间身份变化、清单超时，以及实际 Windows 当前进程创建时间/句柄和错误出生时间拒绝。最终本机439后端、15前端测试与生产构建通过。Windows CI和最终head以对应PR为准；不是干净系统或完整原生交互验收。

本轮未修改个人库、素材或外部AI服务。下一步使用此计量方法完成可重复、同条件、可交互和空闲/切换的完整资源矩阵；长期性能任务仍保留。
