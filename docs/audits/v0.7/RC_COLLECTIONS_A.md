# RC A：大型收藏分页与安全排序

2026-11-07，基线 main `d2a14d4`，独立分支 `codex/collection-pagination-rc`。全部样本独立生成，不读取个人项目或旧 WebUI。

## 实现与兼容

- 复用 Collection、Asset、collection_assets；新增摘要、60 项默认/200 项上限的成员游标页。列表不读取正文、完整元数据或原始路径，缩略图只读取当前页。
- 游标绑定收藏 ID、筛选参数、成员版本及 `(position, asset_id)`。单次响应的版本/计数/成员使用同一 SQLite 读事务；成员和顺序变化返回 409。类型、层级标签交集、星级、喜爱度、日期和现有全文搜索可组合。筛选是实时元数据视图，不是跨请求不可变快照；其他工作区修改标签/元数据后应刷新。
- 跨页选择保留明确 ID，上限1000；偏好复用其他模块的 favorite/stars/preference 命名，作为素材共享属性。追加标签保留旧标签，批量编辑复用 ORM 版本/FTS 事件，每25项flush，同一事务提交，失败整批回滚。移出不删除素材和文件。
- 本页拖拽传完整连续窗口和expected_revision；SQLite首条写语句校验版本并取得写锁，只交换窗口内原有位置。筛选时不允许拖拽；旧重复位置稳定读取，但拒绝分页排序以保护邻页。
- 成员触发器覆盖旧CRUD、OC/音频/生图直接写关联表和FK级联删除；竞争事务只有一个可提交。旧完整API保留，旧排序可选传expected_revision；未升级旧调用仍不具备强制客户端版本保护。旧全量响应没有被伪称已分页。
- 添加members_revision、素材三项偏好列及可重建的顺序索引。沿用迁移前快照/桌面完整备份门槛；不改原排序、正文、历史或文件。生成旧结构及幂等回归通过。

## 规模实测

`PYTHONPATH=backend .venv/Scripts/python.exe desktop/benchmark_collections.py <全新隔离目录>`。

Windows、Python3.13、SQLite3.50；120张256×256 PNG真实生成并通过上传/缩略图API，其余SQL元数据，每5项一项约1120字符生成正文。不是10万文件导入。旧详情与新接口在同一规模/DB测量；旧详情3次、新接口5次，暖态ASGI中位数，含客户端，不是网络/冷启动/渲染。

| 成员数 | 旧详情字节 / p50 ms | 摘要字节 / p50 ms | 60项页字节 / p50 ms | 全游标遍历秒 |
| --- | --- | --- | --- | --- |
| 10,000 | 6,467,377 / 300.10 | 310 / 2.07 | 13,237 / 3.98 | 0.38 |
| 50,000 | 32,419,377 / 1778.08 | 310 / 3.03 | 13,237 / 4.80 | 2.42 |
| 100,000 | 64,859,364 / 3569.72 | 312 / 4.67 | 13,240 / 5.53 | 6.39 |

完整遍历断言全部ID无遗漏/重复，integrity_check=ok。初版分页100k约44.5ms，发现无筛选计数多余联接Asset，修复后约5.5ms。

100k单次tracemalloc峰值：旧详情约650MB，新页约175KB。是Python分配且包括客户端，**不是独立后端RSS/物理RAM节省**。实际HTTP后端在100k浏览/评分/排序后末态采样工作集117.98MiB、PrivateBytes102.45MiB；含启动器/conhost三进程树134.78/109.12MiB。非峰值，未含浏览器/GPU。

隔离库临时移除索引，EXPLAIN为主键查找后`USE TEMP B-TREE FOR ORDER BY`；100k简单顺序SQL p50为9.78ms。恢复索引后为`USING COVERING INDEX ix_collection_members_position`。不在用户库实验。
