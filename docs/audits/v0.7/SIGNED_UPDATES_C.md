## 官方Updater与权限范围

使用固定版本 `tauri-plugin-updater 2.14.0`。本轮核对了已发布crate的checksum和所用API；Cargo.lock通过官方Rust GitHub index正常更新workspace，增加52个依赖项，没有改动系统PATH或安装本机MSVC。

编译参数 `FRONT_UPDATE_PUBLIC_KEY` 未设置或为空时，更新状态为禁用，不注册真实Updater插件。公钥是验证材料，可以随获批准的构建发布；它不是签名私钥。没有通过关闭签名、TLS或版本验证来让空配置看似可用。

界面只获得一个 `desktop_update` 命令，限定 `main` 窗口及本实例确切的回环origin，并再次在命令处理时核对窗口和origin。没有开放通用core、shell、任意URL、任意文件路径或通用执行权限。更新准备接口还必须持有原生外壳的Bearer令牌，普通网页会话不能调用。

## 用户流程与便携版边界

设置页提供更新状态、通道选择、手动检查、说明、下载/验证/备份进度、取消和稍后提醒。启动时在已配置公钥、未延后且没有待处理错误的条件下检查；缺失公钥时明确显示更新未启用。网页模式继续通过部署流程升级。

- **便携版**只下载已通过签名验证的ZIP，不执行安装、不覆盖运行中的文件。用户解压到独立目录并保留原FrontData，或继续使用原自定义数据目录。
- **安装版**必须先完成缓存包验签，再确认安装，生成完整备份并校验隔离恢复。通过后才进入官方安装阶段，停止所属后端，不按进程名清理其他Web或AI服务。
- 如果官方安装程序启动失败，且本实例后端已经被停止，会尝试持久化静态错误代码并重启应用。该分支不等于已验证的安装失败恢复或二进制自动回滚。
- 真正执行安装、安装过程中断或部分文件替换、预览到正式版升级、干净Windows环境中的回滚与数据保留仍未验收。完整数据备份不能替代旧程序二进制的自动恢复。

## 更新前写入屏障与丢响应恢复

更新准备复用现有完整备份/Hash校验/隔离恢复，不增加另一套数据存储。

1. 原生客户端在请求前分配递增request ID，准备与取消使用同一个已知标识。服务端保留取消tombstone，处理“取消先到、准备后到”；相同请求幂等返回原任务，较新请求可以回收丢失响应留下的旧准备状态，旧取消不能释放新屏障。
2. 有排队/运行任务、正在执行的写请求或AI流生成时拒绝安装准备。写屏障保留到备份验证完成、明确取消/失败释放或所属后端停止，避免生成完成但最终数据库提交尚未结束时开始更新。
3. ASGI写请求的保护范围覆盖整个响应体生命周期，包含流式响应结束后的最终写入；AI running标记保留到最终写完。不能仅在发送响应头时释放保护。
4. 完整备份必须为complete并通过Hash与隔离恢复验证。失败、取消或应用生命周期退出释放所属准备状态；前端可显示备份进度。默认不复制外部原地索引文件。

这些保证针对受保护进程中的实际写入路径。真正操作系统崩溃、掉电、安装器部分替换和跨进程同时指向同一活动库的组合，不能从这些自动测试外推为已验收。

## 隔离签名与HTTPS测试方式

`desktop/test_updater.py`创建全新隔离fixture目录，使用官方CLI产生throwaway签名密钥、生成带应用版本的测试载荷签名，再生成仅一天有效的本地CA/HTTPS服务器。测试CA只传给测试客户端，不安装进系统信任库，不关闭TLS验证。

- 本机`--transport-only`只完成官方签名生成和Python HTTPS字节传输，明确输出Rust SDK未运行、未执行安装。
- Windows CI通过独立`.cache/update-test-runtime`安装测试crypto依赖，运行driver并调用`cargo test --release --locked ... updater_tests -- --include-ignored`。这包含真实SDK下载/验签及负向场景，但运行结果尚待CI确认。
- 测试crypto环境与PyInstaller运行环境分离，避免为应用打包测试依赖。测试签名私钥、TLS服务器私钥、测试CA、载荷数据和fixture报告不作为公开附件。
- CI仅上传白名单`stage/artifacts`测试包与依赖锁诊断，不上传测试密钥/数据库/测试目录。没有生成正式信任根或发布正式Release。
